# 多 Agent 零常驻通知设计

日期：2026-09-19  
状态：待用户审阅

## 背景与问题

当前 Windows 原生提醒依赖由 Codex `SessionStart` 钩子启动的常驻 WPF 宿主。宿主意外退出、钩子子进程被清理或启动时序落后于事件时，事件虽然已写入 `events.ndjson`，却没有进程负责展示，造成漏提醒。

项目还需要支持 Antigravity 与 DeepSeek Harness（DSH）。继续为每一种 Agent 维护一个常驻进程，会放大内存占用、生命周期和重复提醒问题。

## 目标

- 支持 Codex、Antigravity、DSH 的完成、待处理、失败与中断提醒。
- 每次事件直接触发一次原生提醒，不保留空闲的提醒宿主或轮询守护器。
- 延续既有三档展示模式、声音开关和全屏策略。
- 保持浏览器工作台只作为配置、预览和诊断入口，不作为桌面提醒的依赖。
- 未安装或未配置的 Agent 适配器不得影响 Codex 的现有使用。

## 非目标

- 不修改任一 Agent 的原生完成提示或音效；此功能仅管理本项目自身的提醒。
- 不推断 Agent 未公开提供的任务状态。
- 不在首个版本中实现跨设备同步、云端服务或后台常驻服务。
- 不承诺通过原生窗口直接跳转任意第三方 Agent 的特定任务；保留任务标识给后续桥接使用。

## 方案选择

采用“规范化事件 + 单次展示器”方案。

```text
Agent 生命周期钩子
        │
        ▼
各 Agent 适配器 ──> 规范化 AgentEvent ──> 隐藏启动器 ──> 单次 WPF 提醒窗口
        │                                                       │
        └──────────────> 诊断事件日志（仅审计）                 └─ 展示结束即退出
```

与持续运行的日志监听宿主相比，此方案不需要进程等待新事件：事件抵达时才创建窗口进程；窗口关闭后进程退出。因此没有空闲内存占用，也不会因监听器提前退出漏掉事件。

## 规范化事件

在现有 `TaskEvent` 基础上增加可选来源字段，保持旧事件兼容：

```ts
type AgentSource = "codex" | "antigravity" | "dsh";

interface AgentEvent extends TaskEvent {
  source: AgentSource;
  eventId: string;
  sessionId?: string;
}
```

- `eventId` 用于同一事件的短时间去重；同一来源和事件标识在本地去重窗口内只展示一次。
- `source` 用于工作台的来源标记、诊断和将来的按 Agent 设置。
- 旧 `TaskEvent` 读取时默认视为 `source: "codex"`，避免历史日志和测试失效。
- 事件只保留任务标题、摘要、状态、时间及非敏感标识；不得记录提示词、密钥、文件内容或完整命令行。

## 各 Agent 适配器

### Codex

- 保留现有 `Stop`、`PermissionRequest`、`Interrupt` 的命令钩子。
- `hook-handler.ts` 从 Codex 标准输入规范化事件后，调用统一通知启动器，而不是仅追加日志等待常驻宿主读取。
- `SessionStart` 不再负责启动提醒宿主；它可以保留为工作台后台服务的独立入口，或在迁移完成后移除。

### Antigravity

- 由安装脚本按用户选择写入 Antigravity 的全局或工作区 hooks 配置。
- `Stop` 映射任务完成；可用的授权/失败/中断事件映射到既有状态，缺失字段时不推断。
- 适配器以 JSON 标准输入或配置中提供的负载为唯一输入，输出同一 `AgentEvent`。

### DeepSeek Harness（DSH）

- 以 DSH 的 `turn/end` 为终态入口，依据结束原因映射 `completed`、`failed` 或 `interrupted`。
- 对等待用户输入、授权和错误采用 DSH 已公开的相应事件；缺失的事件不模拟。
- DSH 适配器作为可选集成：未检测到 DSH 或用户未执行安装命令时，不创建任何 DSH 配置或进程。

## 单次原生展示器

新增一个接收完整 JSON 事件的 PowerShell/WPF 脚本，由隐藏 VBS 启动器调用。

1. 适配器校验并写入审计日志。
2. 适配器向隐藏启动器传递事件文件路径或一次性事件标识，避免在命令行暴露标题、摘要等内容。
3. 展示器读取并再次校验事件和偏好设置。
4. 展示器依据已有策略显示、仅播放声音或抑制。
5. 用户点击“我知道了”、自动关闭或关闭窗口后，展示器进程退出。

事件文件采用应用数据目录中的短生命周期临时文件；展示完成后删除。异常退出时由后续启动进行过期清理。`events.ndjson` 继续作为诊断审计记录，而不是跨进程消息队列。

## 设置与兼容性

现有偏好字段维持不变：

- `mode`：`blocking`、`light`、`hidden`
- `soundEnabled`
- `fullscreenReminderMode`：`normal`、`sound_only`、`disabled`
- `workbenchServiceEnabled`

新增可选的 `enabledSources`，默认启用 Codex：

```json
{
  "enabledSources": {
    "codex": true,
    "antigravity": false,
    "dsh": false
  }
}
```

设置缺少该字段时按上面的默认值处理；保存时再写入完整字段。全屏策略对所有来源一致生效，避免在游戏、视频或直播中出现意外遮挡。

## 迁移与清理

安装或更新时应：

1. 停止并移除旧的计划任务、启动目录快捷方式和提醒监督器。
2. 停止旧的常驻 WPF 宿主。
3. 更新 Codex 钩子为单次通知入口，并提示用户在 `/hooks` 审核新增或修改的钩子。
4. 仅在用户明确启用时安装 Antigravity、DSH 适配器。
5. 保留偏好、历史审计日志和浏览器工作台入口。

卸载时必须仅删除本项目创建的钩子条目与运行文件，不覆盖用户已有的其他 Agent 钩子。

## 故障处理与可观测性

- 每次适配、去重、展示、抑制和展示失败写入本地诊断日志，附来源与事件标识，但不写入敏感正文。
- 单次展示器启动失败时，适配器必须返回非零状态并记录原因；不得静默吞掉错误。
- 无法显示桌面窗口时保留事件日志，供工作台诊断与手动重放。
- 发生重复 Hook 调用时，去重逻辑优先保证同一任务只弹一次，不能因去重而丢失不同任务的提醒。

## 验收标准

1. Codex 完成事件发生后，即使没有任何常驻提醒进程，也能显示一次桌面提醒。
2. 提醒关闭后不存在本项目的提醒宿主、监督器或轮询进程。
3. 轻提醒、遮挡提醒、隐藏、全屏仅声音和全屏关闭策略保持既有语义。
4. 同一 `eventId` 在去重窗口内只展示一次；不同来源或不同事件可以分别显示。
5. Antigravity 与 DSH 未启用时，不产生配置写入、后台进程或 Codex 回归。
6. 完整测试覆盖事件校验、来源默认值、去重、启动参数脱敏、一次性展示器与迁移清理。
